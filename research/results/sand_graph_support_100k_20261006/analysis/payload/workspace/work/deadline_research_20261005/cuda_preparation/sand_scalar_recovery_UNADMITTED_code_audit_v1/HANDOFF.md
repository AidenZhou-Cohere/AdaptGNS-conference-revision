## Fixed root invocation

Use workspace `work/venv/bin/python -B` and this package's `recover.py`. Each
invocation uses the same fixed original state and requires:

```
ACTION --root-execute --package-sha256 MANIFEST
--source-review ABSOLUTE_REVIEW --source-review-sha256 REVIEW_SHA
--route-ready ABSOLUTE_SUCCESSOR_READY --route-ready-sha256 READY_SHA
```

The independent source review must have schema
`sand_scalar_recovery_independent_review_v1`, status
`passed_source_and_synthetic_review`, and `source_manifest_sha256=MANIFEST`.
It is stored outside this immutable package. The controller rehashes every
package member and every original failure/closure binding before acting.

1. **observe** runs one bounded metadata-only remote helper with tag
   `sand_recovery1.fate`. It reads only original saved_A owner metadata, hashes
   its declared scalar product and both exact B target paths, checks the
   original host/boot and all original timeout/owner/child native absence twice,
   and checks assigned A GPUs empty. It writes no remote files. Each B target
   is reported as absent, exact, or conflicting retained bytes.
   Before and after hashing, it also scans native process arguments for the
   exact old frozen inline probe source SHA, including timeout ancestors, and
   the two exact original failed whole-command hashes held by remote shells.
   Any remaining original failed probe/transfer process refuses file-fate
   closure and retains its PID/start/group/command digest in the error evidence.
2. Root obtains an independent review of that actual completed observation,
   with schema `sand_original_scalar_fate_independent_review_v1`, status
   `passed_original_saved_A_closure_and_B_file_fates`, exact `phase_sha256`, and
   `fate_capture_sha256` of `sand_recovery1.fate.json`. All later actions require
   `--fate-review ABSOLUTE_REVIEW --fate-review-sha256 REVIEW_SHA`. A conflict
   refuses recovery and preserves the original bytes. This review is a baseline
   inside the original hour; every later helper freshly rechecks the particular
   original metadata/target state it uses.
3. **close-saved-A** calls the unchanged frozen `close_product` function once,
   remapping only the `sand_saved_A.capture` transport tag to
   `sand_saved_A.capture_recovery1`. No worker is launched. The original failed

   `sand_saved_A.recovery_closure_receipt.json` links it to the new capture tag.
4. **transfer-B-collection** and **transfer-B-audit**, once each, either rehash
   and reuse a previously observed exact final scalar without sending a payload,

5. **complete-transfer** requires both recovery transport receipts, observes

Original capture tag and failed transfer tag are never aliased to successful

## Scope and limits

The new remote fate probe establishes retained metadata and hashes, not numerical
accuracy. The frozen successful saved-array validator retains its original
supported scope. Whole saved-array/scalar products can be large; transfer
completion is not guaranteed. The original phase and all native scientific
deadline guards remain authoritative. A timeout or transport exit alone never
proves remote closure. All failures are kept; there is no automatic retry,
deadline extension, deletion, or replacement clock.

Preparation, imports and synthetic tests create no sockets, inspect no actual
scientific data, and issue no phase. Only explicit root invocations perform the
bounded actual actions above.
