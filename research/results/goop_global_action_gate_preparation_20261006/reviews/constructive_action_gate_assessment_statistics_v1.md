# Prospective constructive extension: predict whether a graph action helps

**Recommendation:** if the complete cost fits after the existing Goop queue is reaped, run one small three-seed **global expand/stay gate** on the three frozen Goop **mix** mean models. Defer the proposed per-particle ranking head. The gate offers the clearest constructive test of the paper's central distinction: residual error and benefit from changing the graph are different targets. This is a prospective recommendation, not an execution release or source implementation. No new test outcomes, training arrays, reserved payloads or model arrays were accessed for this assessment.

The mix arm is fixed for this new study before outcomes: its training already exposes it to both base and random25 graphs with a 0.5 coin. The existing base-arm study remains reported, including adverse results; this follow-up does not replace it or choose favorable seeds. Calling mix the best arm would require evidence and is not the reason for this choice.

## Why a global gate is the cleaner deadline study

Per-particle labels from the base-versus-random25 **whole-graph** intervention measure each particle's response to an entire randomized graph. Ranking those labels to select different individual pairs changes the intervention being predicted; shared endpoints and message passing create interference. A learned ranking may still be empirically useful, but these labels do not identify marginal edge utility. A detached head on previous processor states also needs either an extra base forward or a careful match between previous-action training features and the model's own cached deployed features. That is a substantial new semantic surface before the deadline.

Instead, fix the gate's two available actions exactly: native base or the existing random25 annulus action. Supervise its signed **whole-state** one-step benefit,

`b(x,u) = mean((base_prediction(x)-truth)^2) - mean((random25_prediction(x,u)-truth)^2)`.

The mean is over coordinates and particles. A positive value means that particular random25 action reduced one-step position MSE. A predictor that omits the random draw estimates expected benefit over its declared draws, not marginal pair value. The gate uses the same actions at deployment, so its target has a direct decision interpretation.

Use cheap state-only features of the current six-position history and current graph geometry. A small fixed feature map can contain speed/acceleration magnitude summaries, distances to the known walls, particle count, and available-annulus/base-pair counts. Avoid processor activations and variance-head outputs in this first study. This makes the deployment input identical in definition to the training input, removes score-forward/cache ambiguity, and introduces no additional simulator pass. Teacher-forced training states still differ from autonomous rollout states; explicitly test that distribution shift rather than claiming it is solved.

## One minimal complete design to freeze before implementation

1. **Frozen models:** mix seeds0,1,2 at exactly100k, with all original checkpoint hashes and mean parameters unchanged. One independently fit gate per training seed; no replacement seed or mean-network fine-tuning.
2. **Train-only labels:** all1000 train trajectories at eight predeclared evenly spaced eligible target frames `6,62,118,174,231,287,343,400`. One independently keyed random25 graph per source/frame/model seed; pair base/random predictions on the identical clean state. This is8000 labeled states/model and48000 simulator forwards overall. Generate the label only after both actions, and preserve both outcomes. A guard failure is not a fabricated numeric training target; any omission/fitting rule must be frozen and fully accounted for.
3. **Small predictor:** standardized fixed features and an intercept with ridge regression. Feature/target normalization comes only from the train labels. A tiny fixed ridge grid such as `{1e-3,1e-1,10}` is sufficient; no architecture or feature search. Select one common ridge value using the equal-source, equal-seed validation **decision loss** on the fixed150 same-state validation frames/model. Freeze threshold0 and expand iff predicted signed benefit is positive. Record that this selection metric is one-step, while the primary endpoint is autonomous full rollout. No validation observations enter regression fitting.
4. **Four fully evaluated policies:** always base, always random25, learned gate, and a state-independent random gate. Set each seed's random-gate expansion probability once to the learned gate's validation expansion fraction, without test adjustment. Use fresh predeclared per-source/per-forecast-step random material, independent of whether a gate chooses expansion; an action that is skipped must not shift future random draws. Re-run the two constant policies in this new matched protocol instead of silently reusing incompatible historical RNG/runtime rows.
5. **All test work:** all30 sources, all395 autonomous forecasts, allthree seeds and allfour policies:360 trajectory-policy outcomes and142200 forecast forwards, plus the separately recorded initial parity/setup calls. Report all seed effects, mean and sampleSD; preserve failed full-horizon outcomes as null, accepted H200 prefixes separately, and every never-started or timed-out item. No survivor means or reduced test subset.
6. **Primary interpretation:** report learned-minus-base, learned-minus-random25 and learned-minus-random-gate full-H395 MSE contrasts, not only improvement over a retrospectively chosen weak comparator. Also report expansion fraction, actual added edges, boundary excursions and guarded/missing counts. If the gate effectively selects base throughout, this is collapse to a constant policy, not evidence of successful adaptation. Beating random25 while merely matching base does not establish an accuracy gain from adaptive allocation. Beating the state-independent matched-rate gate is the key check that conditioning adds value; beating both constant actions provides the strongest constructive result.
7. **Runtime:** measure end-to-end state features, graph construction/selection, ridge prediction, simulator forward and transfers; retain setup and training-label generation separately. Use the same method order/repetition design for the four policies on predeclared validation states. The gate has one simulator forward per forecast; that is an implementation property, not evidence that wall time improves. Shared-host CPU/I/O contention remains an explicit limitation.

Validation may also report the paired-action one-step oracle regret and calibration of signed benefit. The oracle only chooses between already computed predictions on common observed states; it is not a deployable policy or an autonomous performance claim. These few values explain failure or success more directly than another battery of residual correlations.

## Cost admission and stopping rule

This is cheap to *fit* but not free to label or evaluate: at least190200 simulator forwards across three seeds, graph construction, full rollout artifacts and byte audits. Do not derive its total runtime from the training update rate or the number of ridge parameters. Before admission, measure a small fixed **train-only** label-generation and feature-extraction capacity probe after source review; use conservative whole-invocation quotas for autonomous evaluation, preserving failure/missing accounting. No new test outcome should choose the design, label schedule, model arm, threshold, ridge grid, or baselines.

B GPUs0/1 become candidates only after the original Goop streams and their parent monitoring loop are fully reaped; Sand2/3 remains independently scoped. Three gate/model seeds on two devices require two waves. Charge both waves, all360 outcomes, validation selection, actual-byte collection, independent review and manuscript integration. Set a prospective compute/analysis completion deadline no later than October7 04:00UTC, preserving04:00–08:00 for writing and author checks. If measured preparation plus that complete allocation does not fit, **decline the study as a whole** and retain the existing paper's adverse evidence. Do not trade away Sand/D3 completion or the writing reserve for an underpowered gate demonstration.

This recommendation improves the contribution only if it closes a practical question: can supervision on actual action benefit yield useful graph decisions under the same fixed mean model? A negative or collapsed gate result is still informative and must remain visible. It would not justify a claim that supervised action values generally fail, since the chosen feature map, one-step target and observed-to-autonomous shift are explicit limits.
