# Pure action-gate fitting from complete committed labels

Preparation only. No real labels or model arrays have been read. The numerical
driver and independent source review must finish before root issues an actual
release. This stage does not admit training-source acquisition or any test
evaluation. It never loads a simulator or unpickles a checkpoint.

```
LEXICAL_VENV_PYTHON fit_goop_action_gate_v1.py --execute \
  --release ROOT_FIT_RELEASE.json --core goop_global_action_gate_core_v1.py \
  --gate-protocol goop_global_action_gate_protocol_v1.md --output-dir FRESH_DIR
```

Use the provided unadmitted release template, setting the final independently
reviewed wrapper/driver pins and the exact six train/validation collection
paths and hashes. Paths refer to the original stopped collection trees on
aquamarine, including all committed NPZs and original source inputs. Run it
there; the tool does not rewrite external paths or accept missing numeric
artifacts in a scalar-only copy. Bind current source, original model/cohort,
data, and collection input bytes in `files_sha256`. Each collection's original
input map is merged without allowing conflicting pins. No test collection is
an accepted input. The wrapper records all fitted candidates and normalizers,
one common validation-selected lambda, and three selected heads.

The complete driver ledger must contain 8000 train and150 validation states
for every seed, with all original integer source/frame identities in order.
Each committed JSON row and NPZ must match its inventory. The wrapper checks
numeric shape/dtype/value hashes and independently recomputes all eleven
features and both coordinate errors/signed benefit. It verifies the unchanged
native edge prefix and both orientations of each selected canonical optional
pair. Graph-source semantics and uniform selection are additionally checked
by the independently reviewed numerical driver; this scalar wrapper is not a
replacement for its native graph and checkpoint admission.

The release's `lineage_paths` must identify the actual driver source, original
training protocol, cohort/audit, training admission, metadata and both split
manifests in its byte map. Its three `models` records bind the real checkpoint
paths/digests to the original cohort's mix members. The `run_config_sha256` is
the driver's canonical checkpoint-configuration digest, not necessarily a
standalone file hash; root records it after the reviewed checkpoint admission.
Every collection must carry the required actual input-path pins, including
the gate core/protocol and its selected checkpoint. Arbitrary scalar digest
claims without that closure cannot be used for fitting. Selected-head
`training_input_hashes` use `train_collection_sha256`, `checkpoint_sha256`,
`cohort_sha256` and `fit_release_sha256`.

All three seeds must use distinct frozen mix100k checkpoints. Each seed's
train and validation model/run-config identities must agree; all six
collections must share original training protocol, cohort/audit, training
admission, core, driver and metadata identities. Any missing, failed,
uncommitted, nonfinite or inconsistent row blocks fitting. Capacity-only
samples cannot initialize a fitted head.

The fixed two-thread CPU setting is established before importing the NumPy
core. The root `max_seconds` and timezone-aware `absolute_stop_utc` bound the
whole invocation, including numeric verification and source rehashing. The
parent operational plan must account for this work and the remaining capacity,
evaluation and analysis reserves; a fit-only completion is not a reason to
drop the full-study cost gate. All sources, label trees and generated heads
are rechecked before the final receipt. Partial outputs and `fit_failure.json`
remain after a failure; no automatic retry, overwrite or resume exists.

`fit_result.json` records the complete input hashes and every candidate,
selected-head and selection digest. It explicitly sets `test_admitted=false`.
Only a later complete train-rollout capacity check and root release may admit
the fixed test grid. The existing Goop/Sand/D3 work and writing reserve keep
priority over this prospective extension.
