# Action-gate numerical driver and scalar-fit interface v1

This interface implements scientific protocol `bc9235fae89d32ede8d1e7f846bff07bdcdd85f4671d5922d688a9535f7fe024` and pure core `d3986c2ac3786e9fc0d36d76339bfeded5448497f7dad9b0559efaaaa53a43ca`. It does not itself authorize any execution.

## Driver CLI

Proposed source `run_goop_action_gate_v1.py`, description-only unless `--execute`. Required mode is one of:

- `train-label-capacity`: train split; exactly64 fixed core.capacity_label_indices states from the8000 schedule; not fitting data or scientific completion.
- `train-labels`: train split; all8000 scheduled pairs for one seed.
- `validation-labels`: valid split; all150 scheduled pairs for one seed.
- `train-rollout-capacity`: train split; fixed min/lower-median/max-particle source IDs×four deployed policies, fullH395;12 cells/seed.
- `test-rollout`: test split; all30sources×four policies, fullH395;120 cells/seed.

Fixed `--seed {0,1,2}`; arm is alwaysmix, objective alwaysfaithful and checkpoint endpoint100000. Other arguments are `--release`, `--repo`, `--benchmark-helper`, `--cohort`, `--cohort-audit`, `--protocol` (original Goop training protocol), `--gate-protocol` (new gate protocol), `--trainer-source`, `--train-admission`, `--manifest`, `--admission`, `--structural-report`, `--acquisition-report`, `--context-semantics`, `--auxiliary-report`, optional `--cross-split-audit` for test, `--checkpoint`, `--checkpoint-sha256`, `--output-dir`, `--cuda-index {0,1}`, `--threads 2`, and `--max-seconds` (positive whole-invocation budget). Rollout modes additionally require `--head` and `--selection` root-bound selected head/global selection files. Split is derived from mode; no CLI split override exists.

Original frozen Goop cohort/checkpoint/source/data helpers perform their original checks; train uses the original train source-admission contract plus this separate gate root release. Valid/test use the original final split contract. Loading and whole-invocation policy execution are owned by this new driver; it does not call an old main or mutate any frozen policy/deadline globals.

Root driver release schema: `adaptgns_goop_global_action_gate_driver_release_v1`, issued_byroot, statusapproved_for_fixed_gate_driver. It binds `mode`, `seed`, `arm=mix`, `checkpoint_updates=100000`, `cuda_index`, `threads=2`, `max_seconds`, `output_dir`, `source_sha256` (all new/local driver/core/helper byte pins), `files_sha256` (every scalar input including checkpoint and optional head/selection), `protocol_sha256` (new gate protocol), `original_training_protocol_sha256`, `host`, physical `gpu_uuid`, and `absolute_stop_utc` no later than04:00UTC October7. The supervisor keeps its own root release and actual process/time/device identity checks. `release_gate(args,now=None)` performs the release/cohort/split/source checks without model or numerical-array deserialization, then returns a context containing args/release/mods/cohort/manifest/admission and input byte bindings. Its output directory must still be absent; preflight never creates it.

Test releases additionally contain `complete_capacity_report:{path,sha256}`, with the same path/hash in `files_sha256`. This separately root-reviewed report must have schema `adaptgns_goop_global_action_gate_capacity_budget_v1`, status `complete_measured_capacity_passed`, `protocol_sha256` matching this gate protocol, `selection_sha256` matching the selected all-three-head receipt, `all_36_rollouts_complete:true`, `all_train_validation_labels_complete:true`, and the timezone-aware global `latest_test_start_utc`. It also retains the calculator's exact `driver_sha256`, `cohort_sha256`, all-three-seed `per_seed` allocation/checkpoint grid, fixed `mapping:{GPU0:[0,2],GPU1:[1]}`, and `cleanup_seconds_per_invocation:15`. Every allocation is a positive integer and all three checkpoint digests are distinct. The selected seed checkpoint and exact whole-invocation quota must match. The scoped parent admits first-wave seeds0/1 by the global latest start and reaps seed0 before launching seed2; the driver independently admits seeds0/1 by that same global bound and seed2 by global bound plus seed0 allocation plus15 seconds. Every invocation also requires current time plus its entire quota to fit `absolute_stop_utc`. The calculator's unpromoted candidate is insufficient. Rollout releases bind standalone selected_seed files and selection JSON using the pure-core `adaptgns_goop_global_action_gate_head_v1` / `adaptgns_goop_global_action_gate_selection_v1` schemas. ## Per-label row and numeric artifact

Each scheduled pair commits one basename `source_000000_target_006.npz` followed by `source_000000_target_006.json`. The NPZ is numeric-only; temporary NPZ is flushed/fsynced then renamed before the row JSON commits. Row schema is `adaptgns_goop_global_action_gate_label_row_v1`. Fields:

- `model_seed`, `arm=mix`, `checkpoint_updates=100000`, `checkpoint_sha256`.
- `split`, `source_index`, `target_frame`, `status` complete/failed, `failure` null or structured category/phase.
- `gate_protocol_sha256`, `protocol_sha256` (the **driver output protocol.json byte hash**), `source_manifest_sha256`, `source_trajectory_content_sha256`, and `history_sha256`.
- Complete rows: `features` list11 float64 values; `base_mse`, `random25_mse`, `signed_benefit`; `pair_rng_material` exactly from the core; `base_graph` and `random25_graph` native audit dictionaries; `prediction_sha256` mappingbase/random25; `network_passes=2` excluding any separately recorded initial parity calls.
- `timing`: feature_seconds, base_graph_seconds, base_forward_seconds, random25_graph_seconds, random25_forward_seconds, paired_action_seconds, scoring_seconds, publication_seconds. Pair wall time includes synchronization/graph/features/forwards/transfers, not future publication.
- `artifact_file` basename, `artifact_sha256` of NPZ bytes, `numeric_arrays` descriptor mapping. Each descriptor has `shape`, `dtype` using NumPy dtype.str, and `value_sha256` of contiguous raw value bytes (same definition as immutable full.state_hash, shape/dtype retained separately).

Complete NPZ keys: `history`float32[6,N,2], `particle_types`int64[N], `features`float64[11], `base_edges`int64[2,E0], `random25_edges`int64[2,E1], `random25_selected_optional_pairs`int64[K,2], `base_prediction`float32[N,2], `random25_prediction`float32[N,2], `base_risk`/`base_raw_risk`/`random25_risk`/`random25_raw_risk`float32[N], `target`float32[N,2], `action_errors`float64[3] orderedbase_mse,random25_mse,signed_benefit. No object arrays. Return any arrays available at a failed phase unchanged, including rejected/nonfinite outputs; incomplete failed artifacts may have a strict subset. Failed row features/errors that were not fully validated remain null, never invented numeric labels.

Both forward actions complete before the target is fetched for label scoring. Any failed scheduled train or validation label commits its failed row/artifact and stops the invocation; remaining scheduled cells are never-started. No fit on survivors, retries, replacement records or failed-label coercion.

## Final label collection

`label_collection.json` schema `adaptgns_goop_global_action_gate_label_collection_v1`:

- status complete / stopped_incomplete_or_failed.
- mode exactlytrain-labels orvalidation-labels for fitting; train-label-capacity is excluded from fit.
- model `{arm:mix, seed:int, objective:faithful, completed_updates:100000, checkpoint_sha256, run_config_sha256}`.
- split, gate_protocol_sha256, original_training_protocol_sha256, core_sha256, driver_sha256, cohort_sha256, cohort_audit_sha256, training_admission_sha256, source_manifest_sha256, metadata_sha256.
- expected_row_ids: ordered[[source,target],...] exactly8000train or150valid (capacity64 separately identified).
- rows: ordered complete/failed scalar row objects, each additionally containing `row_file` basename and `row_sha256` of the separately committed JSON. `row_file`/`row_sha256` exist in the aggregate only, avoiding a self-hash cycle.
- required_rows, committed_rows, complete_rows, all_required_labels_complete, and coverage list with everyexpectedID/state (committed_complete, committed_failed, never_started). A supervisor interrupt/current timeout may leave artifacts without a row; those stay in inventory and are not a complete label.
- input_sha256: original root release, all original cohort/protocol/helper/model/data/metadata/evidence bytes, including every source array required by its admitted manifest.
- files: relative filename→`{sha256,bytes}` for every ordinary output then present, including partial outputs and protocol/status/rows/artifacts; exclude `label_collection.json` itself. output_tree_entries includes directories and files with the same exclusion.
- all_inputs_reverified:true only after final byte checks; publication verifies current row/artifact/protocol bytes against their original committed hashes, requires aggregate rows to equal committed JSON without their extra row-file/hash fields, serializes the collection and repeats source/input and output-tree checks immediately before exclusive final publication. Numeric publication independently compares serialized NPZ value/shape/dtype descriptors to the original arrays before committing rowJSON. Row and collection serialization also compare parsed output bytes and the post-serialization scalar object against an independent pre-serialization deep snapshot; they return the parsed exact bytes.
- runtime includes actual setup, paired-action processing/publication, total before publication and declared budget; failure/abort and last current ID remain explicit.

Root fitting wrapper accepts only complete train-labels and validation-labels collections, all three integer seed IDs, all required ordered rows complete, zero missing/failed labels, and all_inputs_reverifiedtrue. It must match the same frozen seed/checkpoint/run-config/cohort/training-admission/original-protocol/core/driver lineage across train andvalid, while manifests differ by split. Require all rowJSON and referenced NPZ bytes locally to the wrapper, validate scalar/array descriptor correspondence, and use saved features/errors; core math provides optional independent recomputation from history/prediction/target without simulator imports. New root fit release binds the exact six collection digests and final driver/core/protocol pins. Emit every ridge candidate, full common-selection diagnostics, and three selected heads; no test files enter this wrapper.

## Rollouts and deadline

`rollout_collection.json` schema `adaptgns_goop_global_action_gate_rollout_collection_v1` retains all120test or12train-capacity cells/seed with the same provenance/publication rules. Every forecast records requested action, effective budget, per-step keyed pair/gate RNG material, graph audit, feature/gate cost, forward count, MSE/boundary accepted prefix and failures. Target is read only after prediction. Full-H395 summaries remain null after failure; H200 is pointwise. Separate selected head and common-selection hashes bind every row. Parity/setup calls stay separately charged. Successful parity has two calls; if its helper raises before returning, actual parity count is explicitly unknown. Deployed `network_passes` counts supplied-forward attempts; all complete rows have exactly395. `feature_trace` stores accepted learned-gate feature vectors only and has zero rows for the other policies.

Rollout row schema is `adaptgns_goop_global_action_gate_rollout_row_v1`; rows include full `steps`, `mse_per_step`, `completed_steps`, `mean_rollout_mse`, `mse_at_final_horizon`, `mse_at_declared_trace_steps`, `requested_expansion_fraction`, `effective_expansion_fraction`, `zero_budget_fraction`, `network_passes`, `native_parity_network_passes`, `native_parity` and `timing`. Complete rows retain prediction/ground-truth arrays plus trace graphs at1/10/50/200/395; failed rows retain accepted prefixes, failed input, any rejected outputs and available parity values unchanged. No incomplete prefix is promoted to a full-horizon metric. Base/always-random and learned/random gates use the original graph helper policy names, with no mutation of frozen globals.

Collections report `runtime.setup_seconds` (release validation, source/CUDA/model/parity/protocol setup), `case_timings[].wall_seconds` (each calculation plus NPZ/rowJSON publication), and `runtime.elapsed_before_collection_seconds` (through final model/input verification and status writing). Final collection publication overhead is measured externally by the scoped parent because it cannot be known inside its own serialized bytes. Timeout is `execution_budget`, never a numerical guard; the accepted current prefix is returned and published after leaving the one-shot calculation alarm, then later work stops. All test cells committed with only scientific guards produce `complete_with_guard_failures` and exit0 after source/model revalidation; any label/capacity failure, execution error, parity failure, budget failure or incomplete coverage exits1. An artifact/publication integrity failure leaves failed-publication evidence and no successful final collection.

Complete preparation/capacity and fit-only stages do not admit test. The protocol's complete36 train-only capacity rollout outcomes, every label/validation pair and reviewed full remaining-cost arithmetic must pass before a root test release. Parent allocation must preserve the04:00UTC compute/analysis deadline, writing reserve and scoped B0/1 ownership without controlling Sand2/3. No source/model/data execution has occurred while authoring this interface.
