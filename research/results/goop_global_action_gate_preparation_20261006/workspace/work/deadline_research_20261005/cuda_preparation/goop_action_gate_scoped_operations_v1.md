# Goop global-action gate: root admission and complete costs

The prospective scientific contract remains `goop_global_action_gate_protocol_v1.md` (bc9235fa). The scoped supervisor runs one explicitly admitted phase, on B GPUs0/1 only, after all original Goop trainers/evaluators and their supervisors have exited. It observes Sand GPUs2/3 without signalling or adopting their processes. GPU0 runs mixseed0 then mixseed2; GPU1 runs mixseed1. ## Preparation costs before fitting

1. **64-state label capacity per seed.** Root assigns three bounded invocations of `train-label-capacity`, following the fixed two-GPU placement. They must all finish every paired action, source check and row/NPZ publication. Any missing/failed sample stops preparation. These192 states are not substituted for fitting labels.
2. **Full label/validation budget.** `goop_action_gate_cost_plan_v1.py` reads the three complete scalar collections, matching stopped parent outcomes and original full train manifest. For seed s, q_s is the maximum measured paired-state wall time over64 states, including row publication. Let a_s be measured setup and f_s=max(0,parent elapsed−a_s−sum(case wall times)), accounting for finalization and remaining whole-process overhead. Full train allocation is ceil(a_s+1.35×8000×q_s+f_s); validation allocation is ceil(a_s+1.35×150×q_s+f_s). The two-GPU phase allowance is max(seed0+seed2+30,seed1+15), where15seconds/invocation is bounded cleanup. The1.35 margin is an engineering allowance, not an empirical worst-case bound.
3. **All train labels and all validation labels.** Run separate `train-labels` and `validation-labels` phases with those reviewed whole-invocation allocations:24000 train states and450 validation states in total, each with two simulator forwards. All required rows must be finite and complete. Retain failures and remaining never-started identities; never fit on survivors. Actual total preparation accounting includes the192 capacity pairs, full training/validation pairs, all parity calls, original input/model hashing and conversion-free data checks, row/array serialization, stopped scalar reading and process finalization. Preserve both each child's wall time and concurrent phase wall time; summing GPU durations is not elapsed critical-path time.
4. **Complete CPU array audit, fit and selection.** Root must budget the full array/row/hash audit for six collections, all fixed float64 ridge candidates, validation decision losses, common-lambda selection, publication/rechecks and immutable head transfer. `fit_goop_action_gate_v1.py` owns these checks and exact fitting. Do not treat the11×11 solve time as the whole fitting cost. Record actual elapsed fit/audit time and source revalidation, and retain enough time for the next capacity phase and all remaining original studies. The label capacity extrapolation does not measure this CPU/input cost; root supplies a bounded allowance before admitting full preparation.

All of the above are spent preparation cost at the later test decision. The supervisor has no cross-phase automatic advancement. Root reviews complete outputs and recomputes remaining time after each phase. No source, head, threshold, seed, feature or schedule search is permitted.

## Measured final cost gate

5. **36 full train-only rollout capacity outcomes.** With the common selected lambda and all three heads frozen, run `train-rollout-capacity`: min/lower-median/max particle-count sources ×four deployed policies×three seeds, all395 forecasts. All36 must complete with finite measured wall costs. A scientific guard also fails capacity; it cannot be dropped or reinterpreted as a fast rollout. This phase needs its own bounded root allowance; neither label timings nor a reduced-horizon pilot establish its completion cost.
6. **Complete final arithmetic.** For each seed/policy, take the maximum full-case wall time across its three capacity sources. Test R_s=ceil(setup_s+1.35×30×sum_policy(max_case_sp)+parent_finalization_overhead_s). The concurrent test allowance is max(R_0+R_2+30,R_1+15). Reserve900seconds for remaining input/preflight work,2700seconds for complete scalar/array collection and3600seconds for independent analysis/manuscript integration. Already completed input/preflight may remove the900seconds only when an actual byte-bound, dated root completion receipt matches protocol/cohort/selection. The calculator loads that receipt and preserves its actual elapsed cost as spent. Collection and independent analysis reserves cannot be declared already spent before test outcomes exist.
7. **Root final admission.** The calculator emits only `candidate_requires_root_review`; it does not claim that fitting/labels were independently reviewed or authorize test. Root must verify the complete train/validation/fit records, all36 capacity outcomes, all fixed sources/checkpoints/heads/selection, actual setup/transfer/input costs and remaining time. If they pass, root writes a separate `adaptgns_goop_global_action_gate_capacity_budget_v1` receipt with `status=complete_measured_capacity_passed`, `all_train_validation_labels_complete=true`, `all_36_rollouts_complete=true`, unchanged measured arithmetic and exact provenance. Failure or insufficient time declines the complete test study; no source/policy/seed/horizon reduction is implied.
8. **All360 test outcomes.** Run `test-rollout` for all30 sources×four policies×three seeds. Only the initial seed0/1 starts are subject to the global latest-test-start boundary. Seed2's latest is that global boundary plus R_0+15seconds, and its own quota must fit the common absolute stop. Parent admission checks the complete two-wave allocation; each child independently checks its corresponding quota, immutable model and applicable start boundary. A complete test grid containing scientific guards remains a complete failure-accounted grid: continue all planned sources/policies/seeds and leave undefined full-horizon means null. Execution errors, incomplete grids and timeouts stop the phase and retain missing work.

## Supervisor interface

Use absolute lexical venv Python; do not resolve it to the system interpreter. The entry is `supervise_goop_action_gate_scoped_v1.py --execute --release ABS --output-dir NEW_ABS`. Each root release fixes mode, three complete child argv arrays and child releases, model/source/data/selection/capacity hashes, original closed Goop PID/start identities, fresh clock evidence, exact four physical UUIDs and B0/1 ownership. All three scalar driver gates run before any launch. During active work only lightweight immutable metadata/process checks run; full hashing and large collection parsing wait until all owned children are reaped.

The parent reuses the reviewed D3 Runtime/identity-safe signalling/reaping and Sand scoped GPU checker without altering their source. Each child registers before fallible identity checks. The parent escalates only its own children SIGINT→SIGTERM→SIGKILL within15seconds. An unreaped child prevents final phase publication and any following seed. Driver output arrays remain in place for the fit/root collector; the parent hashes its own evidence and completed scalar collections, without silently rehashing every large NPZ while GPUs are active. `process_outcomes.json`, partial files and failures remain even if final ledger publication fails.

`goop_action_gate_cost_plan_v1.py --execute --input BUNDLE_JSON --output NEW_CANDIDATE_JSON` is scalar arithmetic only. The bundle contains mode, protocol/driver/cohort/train-manifest hashes, `train_manifest:{path,sha256}`, and `collections`/`process_outcomes` maps keyed0/1/2 with actual file references. Rollout mode also includes selection hash, bounded clock error and optional `completed_outer_stages.input_preflight:{path,sha256}`. Per-seed parent outcome files are the supervisor's `logs/mix_seedS.outcome.json`; they bind actual child command/model/device and measured elapsed duration. Candidate results and complete unsuccessful inputs are retained, including a false `complete_remaining_work_fits` result.
