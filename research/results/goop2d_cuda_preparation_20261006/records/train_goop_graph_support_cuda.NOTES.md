Preparation only. `train_goop_graph_support_cuda.py` creates no processes or data by default. Root owns every real numerical check, timing run, six-model release and scientific launch. Sand sources and runs are unchanged. No Goop arrays, models or outcomes were used in preparing this candidate; the actual source manifests and structural metadata were read.

## Exact data and context admission

This entry accepts only the complete official Goop train source: 1,000 trajectories, 401 stored frames, 395,000 six-frame training histories, float32 two-dimensional positions and preserved int64 per-particle type 7 vectors. Source object generation, CRC, byte length, SHA256, complete TFRecord offsets/payload hashes, converter/reader, metadata and train-manifest hashes are pinned. Scalar type substitution, Sand schema/ZIP fields, unknown auxiliary fields, incomplete counts and alternate horizons are rejected. Native Goop normalization comes from the exact official metadata, never Sand statistics.

The stored `step_context` arrays remain in place and are verified before and after a run. Their exclusion from model inputs requires two separate pieces of root-bound evidence:

- `goop_context_semantics_review.json` plus its four files in the adjacent `goop_context_semantics_sources/` directory. The official GNS parser at commit `f5de0ede8430809180254ee957abf36ed62579ef` selects `step_context` only when metadata contains `context_mean`. Goop's exact metadata has neither `context_mean` nor `context_std`, so the released parser/model input contract does not use the stored auxiliary. No source prose was located naming the NaNs a placeholder.
- Root's `goop_auxiliary_v1_report.json`, generated by `audit_goop_auxiliary.py`, schema `adaptgns_goop_auxiliary_census_v1`, status `all_preserved_auxiliary_bytes_verified`. The trainer checks the complete 1,000-row train census and independently rechecks actual context NPY length, SHA, dtype, shape, the actual 400 finite positive-zero values plus one NaN (no infinities), and exact float32 bit patterns `00000000`/`7fc00000`. These are integrity conditions, not the semantic justification for omission.

Do not alter the converter's retained `use` descriptor; the root admission records the reviewed interpretation separately. The nonadmitted template `goop_training_admission.template.json` lists the required fields. Root must verify both report hashes against actual reviewed evidence and set `status` to `admitted` only after source/structural/context review. This data admission does not certify CUDA repeatability, model quality, deadline fit or authorize a scientific run.

Required execution arguments are:

```text
--execute --repo REPO --train-manifest NUMERIC_ROOT/train.json
--admission ROOT_DATA_ADMISSION.json --structural-report goop_structural_v1_report.json
--acquisition-report goop_acquisition_v1_report.json
--context-semantics goop_context_semantics_review.json
--auxiliary-report goop_auxiliary_v1_report.json
--protocol LOCKED_GOOP_PROTOCOL.md --output-dir FRESH_RUN_DIRECTORY
--arm base|mix --seed 0|1|2 --updates 100000 --cuda-index ASSIGNED_GPU
```

`metadata.json` and the numeric `train/` directory must be adjacent to `train.json`. Official context source files must be adjacent to the semantics report under `goop_context_semantics_sources/`. The acquisition report is byte-pinned; the trainer does not download or reconvert anything. Copying a report to another host preserves its bytes.

## Numerical recipe and lineage

The model, faithful objective, sampling/noise stream, learning-rate schedule, graph RNG, exact native prefix and optional-edge budget, strict Adam checks and RNG restoration are reused without numerical changes from pinned `train_sand_graph_support_cuda.py`. The run loop differs only in Goop names and an added final evidence/auxiliary recheck. AST comparison is an explicit test. Architecture remains width 128, 10 message-passing blocks, two MLP layers, six-frame histories and batch two. Noise remains 6.7e-4; clamped variance floor 1e-6; detached faithful features; Adam 1e-4 to 1e-5 across 100,000 updates, foreach/fused disabled.

New schema: `adaptgns_goop_graph_support_cuda_training_v1`; checkpoint field `cuda_goop_graph_support_schema`; embedded training-config key `cuda_goop_graph_support_run`. No Sand, earlier WaterDrop, opposite-arm or short-endpoint checkpoint initializes a fresh scientific run. Checkpoint/status/protocol byte pins, failed-attempt preservation and explicit same-host dead-PID resume remain intact. `--stop-after 512` is available solely for separately released infrastructure work; such a checkpoint is incomplete and must never become a scientific endpoint or parent of a fresh scientific run.

This candidate is bounded to the same pinned Torch 2.13.0+cu129/GB200 stack with deterministic algorithms and `CUBLAS_WORKSPACE_CONFIG=:4096:8`; it asserts no CPU/CUDA bitwise equivalence. Root must admit Goop actual-data finite forward/gradient, native-base and same-CUDA replay behavior independently before model releases.

Full evaluation is a separate entry and release. The prospective study uses all 401 stored frames: six observed plus 395 forecasts. The released TensorFlow convenience evaluation removes the final stored frame and uses 394 forecasts. Describe 395 as the declared complete stored-trajectory horizon, not an exact reproduction of that TF evaluation path.
