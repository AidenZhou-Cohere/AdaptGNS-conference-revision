# Running the separate Sand scoped supervisor

Authoring only: no real training, checkpoint loading, official arrays or test
source were used to prepare this adapter. Default invocation is description
only. Root owns the actual independent review, exact host release and launch.

The files are `supervise_sand_scoped_science_v1.py`,
`sand_scoped_operational_amendment_v1.md`,
`sand_scoped_schedule_fixed_spec_v2.json` and the three
`sand_scoped_{scientific_release,process_check,clock_check}.template.json`
templates. All templates are unadmitted. The scientific release's file map
uses the exact semantic keys shown, not a self-referential release digest.
The release hash is captured independently into the launch record.

Explicit CLI inputs are:

```
--execute --host-role A|B --release PATH --repo PATH --trainer PATH
--capacity-source PATH --lifecycle-source PATH --verifier-source PATH
--train-manifest PATH --admission PATH --structural-report PATH --protocol PATH
--schedule-plan PATH --amendment PATH --process-check PATH --clock-check PATH
--python PATH --output-dir PATH
```

Ordinary input paths resolve to absolute original locations. Preserve the
interpreter's exact lexical absolute `sys.executable` spelling, including a
`.venv/bin/python` symlink; do not resolve its target for child argv. Launch the
supervisor itself with an absolute path without `..`. Use a fresh output
directory. The root `python_environment` receipt binds lexical path, resolved
binary/hash, `sys.prefix`, `sys.base_prefix` and any `pyvenv.cfg` path/hash.
The semantic file map additionally includes `python_target` and, when present,
`python_venv_config`. Full byte and active metadata checks cover the lexical
interpreter, target binary and venv configuration.
No arbitrary child argv is admitted: the imported immutable scientific helper
constructs the100k/two-thread/log100/checkpoint10k faithful base/mix command.
No optional stop-after, resume, lock clearing or alternative endpoint exists.

Source requirements are the unchanged Sand graph trainer and all its numerical
pins; original capacity/lifecycle and scientific-verifier files; original
scientific protocol; new fixed schedule and amendment; admitted Sand train
manifest/structural report; and a concrete root release. The trainer continues
to record the original v1 scientific protocol hash. Host launch and summary
add the amendment/spec/scoped-supervisor hashes, so amended operational
provenance is explicit without changing numerical training configuration.

RoleB owns GPUs2/3 for seed0. RoleA owns GPUs0..3 for seeds1/2. Root must bind
all four physical UUIDs, exact semantic mapping, full GPU inventory and native
identity closure records. At least a prior Goop trainer and the original broad
training supervisor must have stopped/reaped or exited. The entire original
training supervisor, including CPU endpoint audit, must exit. A persisted
`verifying_endpoints` state alone is insufficient. RoleA additionally requires
all former Goop-owned GPU work reaped. No live handoff is supported.

Process and root-reviewed clock records must be within300seconds; clock error
is0..5seconds. Native prelaunch reads verify former identities are absent and
no original broad monitor or duplicate Sand trainer remains. OnB, unrelated
GPU0/1 activity is retained without control; only owned GPUs must be exclusive.
An owned Sand PID on any wrong GPU is a failure. Captured PID/parent/start/argv
and physical UUID are checked; stale samples of reaped/now-absent owned children
are distinguished from live reused PIDs. Signals apply only to captured owned
process groups through the unchanged reviewed lifecycle.

Large inputs are fully rehashed before launch and after all owned children
are reaped. Cached inode/device/size/mtime/ctime checks run during training;
there are no heavy repeated source hashes in active child polling. The frozen
trainer verifies admitted data itself. GPU queries run asynchronously with
bounded native query time. Full inventories and trainer-status observations
are preserved; raw observations are recorded before classification. Reaping
is cheap while peers run; full checkpoint/history/Adam/pairing inspection runs
only after every assigned trainer is reaped. Root must still freeze the
complete six-model cohort and do all source/test checks before evaluation.

Both roles enforce the same latest actual launch15:05UTC and training/audit
stop22:44UTC on Oct6, with the fixed27404.671591931674second whole-training
allowance and18960second posttraining reserve through04:00UTC Oct7. Root may
choose an earlier latest launch. The supervisor rechecks time after setup and
process checks immediately before each child. Cutoff, implementation failure,
interruption, duplicate/foreign work or changed source stops further work and
preserves failed/incomplete outputs. No numerical retry is automatic.

`wave_A.json`/`wave_B.json` retain all started and unstarted jobs, external
process outcomes, signals, final inventories, failures and remaining owned
children. `worker_summary.json` is written only after unchanged full endpoint
and pairing validation passes. Host summaries are not complete-cohort or test
admission. Any unreaped child, missing100k endpoint, pairing mismatch, changed
source or exceeded allocation leaves the host study incomplete; retain all
earlier failure logs and artifacts rather than manufacture a completed mean.
