# D3 final evaluation supervisor

`supervise_goop3d_final_evaluation_v1.py` is a new operational adapter, not a change to the frozen trainer, evaluator, diagnostics, scientific protocol or numerical implementation. It describes scope by default. Only explicit `--execute` with the complete root release and canonical absolute input paths can start work. All authoring tests use synthetic scalar receipts, opaque checkpoint/NPZ bytes and fake processes; no actual source arrays, checkpoints, GPUs, reserved-test requests or processes are used.

The fixed completed cohort is the separately frozen six-model prospective Goop-3D study. The adapter binds its exact plan, protocol, scientific freeze source, reserved-test wrapper, strict scalar collector and ledger interface. The root gate applies the unchanged evaluator cohort gate to every model before any test manifest/preflight read. The reserved source must already have passed the reviewed checksum/conversion/census/admission preflight. Root issues every child release; this supervisor neither manufactures child scientific admission nor chooses checkpoints.

Root prospectively fixes one complete stage order and per-stage whole-invocation quotas, identical for all six models. An order placing clean/same-state diagnostics before expensive autonomous rollouts is allowed if declared before execution. Every stream still has all five required stages. Root provides all30 complete direct evaluator argv/release pairs. Commands must execute the exact absolute evaluator via the pinned interpreter, with optional -B/-u only, all recognized named options, two CPU threads, the correct physical GPU, original model/cohort/split inputs and fresh stage directory. No shell, inline code, module launch, unknown flag, retry or resume is supported.

One dedicated four-GPU host uses fixed waveA base0/GPU0, mix0/GPU1, base1/GPU2, mix1/GPU3; waveB base2/GPU0, mix2/GPU1 starts only after all waveA children are reaped. Each stream runs its five stages serially. Do not overlap this dedicated-host queue with unrelated GPU work. The later GPU-scoped Sand work is a separate adapter/protocol amendment, not this supervisor.

Each quota is1..7200seconds from the beginning of Popen, including setup, hashing, inference and publication. The two longest-wave allocations plus15seconds of cleanup per invocation and an explicit supervisor audit reserve (at least60seconds) must fit the frozen21600-second operational activity allocation. The absolute queue stop must leave the frozen3600-second analysis reserve before2026-10-07 01:00UTC. This is a fixed allocation after unsuccessful complete-horizon timing, not a runtime forecast or promise of complete outcomes. Root supplies fresh bounded clock evidence, an absolute latest start and stop, physical UUIDs and the whole-supervisor outer timeout. Eager source/data preparation must finish before this queue's concrete release is issued.

Full input bytes are checked before first launch, between fully reaped waves and before ledger publication. During active scheduling only cached inode/size/mtime/ctime metadata are checked, followed by a fresh clock/abort check immediately before launching another child. The frozen child independently rechecks its complete execution inputs. This avoids blocking active child deadlines with repeated large checkpoint/data hashes. Timing receipts include observer lag; the supervisor does not claim real-time signal delivery.

Owned children are registered before identity inspection. PID, parent, start ticks and exact argv are captured. The unchanged reviewed lifecycle signals only a matching owned process group, using SIGINT at quota expiry, SIGTERM after5seconds, SIGKILL after10seconds and a15-second cleanup ceiling. Identity refusal or remaining children prevents later work and strict ledger admission. Repeated interruption signals are suppressed only during bounded cleanup; all handlers are restored afterward. Malformed scalar failure receipts must not interrupt cleanup of another owned child.

GPU inventories are queried asynchronously with the owned set captured at query start. Currently live PIDs must match captured start/parent/command identity; a reused live historical PID cannot inherit ownership. An already reaped, now absent owned child can be labelled a stale query sample. All raw inventories and classifications are retained. No unowned process is signalled.

Scientific guards remain saved failed outcomes. Whole-invocation quota expiry and the evaluator's inner TimeoutError can end a stage without retry; current uncommitted cells are timed-out only when supported by a current identity and explicit timeout. Other missing cells remain missing; unstarted stages retain all scheduled cells and their exact child releases. Implementation, data, unexpected exit or malformed failure receipts abort subsequent work for root review. Full-output coverage is established only from complete actual-N manifests and the unchanged evaluator schedules.

After all owned processes are reaped, the adapter writes a strict30-stage supervisor-candidate ledger. It records committed JSON and opaque NPZ hashes, all scientific failure objects, every missing cell, exact process receipts, full stopped stage trees, parent logs/wave receipts/release snapshot and control-input hashes. The current queue status and ledger itself are excluded from the parent inventory to avoid circular hashes; queue status is separately byte-checked. The ledger is serialized before final input/tree/status/clock checks and published last. Parent elapsed time is explicitly `elapsed_before_publication_seconds`, not whole-supervisor wall time. A publication failure retains process outcomes and failure evidence without a strict ledger.

The ledger's row audit is intentionally narrower than the separate scalar collector: it verifies identity/status/horizon/opaque bytes, not every scientific scalar formula. Root must independently review stopped outputs and issue a separate collection release, then a separate fixed-analysis release. The collector remains authoritative for complete scalar arithmetic, grids, boundary/graph identities, failed/missing denominators, paired effects and measured-call clocks. No successful-prefix means or conference-readiness claims are produced here.

Use all of `--release`, `--output-dir`, `--plan`, `--cohort`, `--cohort-audit`, `--protocol`, `--trainer-source`, `--valid-manifest`, `--test-manifest`, and `--test-preflight` with `--execute`. The template is deliberately incomplete and unadmitted. Ordinary input paths are canonical absolute paths. Every child interpreter must preserve the exact lexical absolute `sys.executable` spelling used to launch this supervisor, including a `.venv/bin/python` symlink; do not resolve that symlink for argv. Launch the supervisor itself with an absolute path without `..`. The root `python_environment` receipt binds this spelling, resolved binary and hash, `sys.prefix`, `sys.base_prefix` and any `pyvenv.cfg` path/hash. `python_files(receipt)` supplies the lexical binary, target binary and venv configuration entries for the complete file map. Full byte and active metadata checks cover these paths. The root release file hash is captured separately and cannot be self-included in its own file map.
