# Reserved Goop-3D test preparation

`prepare_goop3d_reserved_test_v1.py` is a new, separate, description-only-by-default wrapper. It does not modify or replace frozen training, numerical evaluation, the original train/valid converter, source data or protocol. Its five explicit modes are `inspect`, `acquire`, `convert`, `census`, and `preflight`. Every invocation needs its own root release, fresh output, exact input path/hash closure, all six frozen scientific endpoints and complete root paired audit. The endpoint comes from the prospective completed cohort; it is not assumed to be100k.

No real reserved source headers or numeric values were accessed in authoring/testing. Tests use synthetic TFRecords, fake HTTP, synthetic root receipts, fixed public metadata and reviewed source code. Tests that compose census and the unchanged evaluator explicitly substitute synthetic train/valid manifest hashes in memory; frozen modules on disk remain unchanged.

## Required sequence

1. Root independently completes and freezes the scientific cohort and records `created_utc`. Prepare an `inspect` release only after that timestamp. The wrapper applies the unchanged D3 evaluator cohort gate to all six cells, including the exact protocol/trainer pins, and requires the initial empty-Adam check as well. It does not deserialize checkpoints or inspect running processes; root's prior byte/tensor/process audit remains necessary.
2. Run `inspect` to save publisher headers from the fixed official Goop-3D `test.tfrecord` URL. There is no baked-in test checksum, source count or key convention. Only HTTP200, identity content encoding, positive length, numeric generation and a four-byte CRC32C are accepted. No body download occurs.
3. Root reviews those retained headers and issues a new `acquire` release binding their bytes and a fresh acquisition directory. GET is pinned to the observed generation; response length/generation/CRC must match HEAD exactly. It checks streamed length and CRC32C, computes SHA256, retains partial bytes and failure receipts, and never retries/resumes automatically. Metadata is a hash-verified local copy of the frozen471-byte official metadata. The directory contains the original numeric source and acquisition receipt.
4. A new `convert` release binds the actual source, acquisition receipt, source-header receipt, metadata and frozen reader. The wrapper calls the unchanged `prepare_goop3d_official.py` helpers `verify_source`, `convert_one` and `verify_arrays`; it does not broaden that module's train/valid-only CLI. Every TFRecord CRC and complete-source EOF/SHA/CRC check remains active. All source element bytes, keys and auxiliary arrays are preserved. The complete decoded record count is discovered, then T301/D3/type7 and H295 are required. Unexpected structure remains in staging with its report; no subsampling, padding or array repair occurs.
5. A new `census` release binds the complete numeric test output, original fixed1000-train/100-validation manifests, context source review and acquisition. The wrapper rehashes all train/valid/test position/type arrays, independently calculates exact element-content identities, reports within/across-split duplicates and applies the unchanged D3 auxiliary census to every record, including absent auxiliary arrays. It rechecks all numeric and official-context source bytes. Source-key and auxiliary-value patterns are not invented or borrowed from 2D. A duplicate/failure is retained and no admission candidate is published.
6. Successful census emits `auxiliary_report.json`, `cross_split_audit.candidate.json`, `verified_input_bytes.json`, and `final_test_admission.candidate.json`. Both admission candidates explicitly say `preparation_wrapper_not_root` and require root review. Root creates separate authoritative copies: cross-split audit uses `issued_by:root`, `status:all_required_splits_verified`; test admission uses `issued_by:root`, `status:admitted` and binds the actual authoritative cross-audit hash. Preserve the candidates. Do not activate them merely by renaming files.
7. A new `preflight` release binds those root admissions and every split-evidence file. The wrapper calls unchanged `evaluate_goop3d_graph_support_v1.py::check_split` with the byte-pinned numeric data loader, then recomputes the fixed actual-N source grid and same-state schedule. It runs no inference, clean validation, training or model selection. It records all evidence hashes and failures. Root must independently review before preparing any final evaluation release/queue.

All final-evaluation source grids remain the unchanged evaluator's schedule: every source if actualN≤30; otherwise30 indices floor(j(N−1)/29), six policies, H295. Test same-state target frames are7,80,153,226,300. Clean validation remains validation-only. The future final evaluation ledger's30 stage receipts and all success/failure denominators are unaffected by this wrapper.

## Root release and invocation

The inert JSON template is not executable admission. Root sets status to `approved_for_MODE`, mode to the matching CLI mode, current endpoint and cohort/audit hashes, exact output absolute path, and `files_sha256` to the **exact** path set returned by `input_paths` for that mode. The release date must follow cohort freeze; source headers must precede every consuming release. Each operational mode checks its bound source/input hashes before work and before successful publication. Root supplies a whole-invocation outer timeout; the source checks the2026-10-07 01:00UTC compute cutoff, including acquisition chunks. These commands should be run only on the root-approved host after all prerequisites are reviewed.

Every mode includes `--execute --mode MODE --cohort COHORT --cohort-audit AUDIT --root-release RELEASE --protocol SCIENTIFIC_PROTOCOL --trainer-source FROZEN_D3V2_TRAINER`.

- `inspect`: `--output FRESH_HEADERS_JSON`.
- `acquire`: `--source-metadata HEADERS --metadata FROZEN_METADATA --output-dir FRESH_ACQUISITION_DIR`.
- `convert`: `--source-metadata HEADERS --input-dir ACQUISITION_DIR --acquisition-report RECEIPT --reader FROZEN_READER --output-dir FRESH_NUMERIC_DIR`.
- `census`: `--source-metadata HEADERS --numeric-root NUMERIC_DIR --train-manifest COMPLETE_TRAIN --valid-manifest COMPLETE_VALID --acquisition-report RECEIPT --context-semantics CONTEXT_REVIEW --output-dir FRESH_CENSUS_DIR`.
- `preflight`: `--source-metadata HEADERS --numeric-root NUMERIC_DIR --admission ROOT_TEST_ADMISSION --acquisition-report RECEIPT --context-semantics CONTEXT_REVIEW --auxiliary-report AUXILIARY_REPORT --cross-split-audit ROOT_CROSS_AUDIT --data-loader FROZEN_NUMERIC_LOADER --output FRESH_PREFLIGHT_JSON`.

Outputs are never reused for a fresh mode/attempt. Running-status files update atomically within one attempt; completed/failed directories and partial/staging bytes are retained. The wrapper does not upload data, run models, launch workers, send messages, select endpoints, acquire compute, or infer conference readiness.
