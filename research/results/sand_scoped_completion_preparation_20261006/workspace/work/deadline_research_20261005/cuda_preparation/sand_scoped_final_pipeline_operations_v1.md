# Sand scoped final pipeline

This separate pipeline implements the fixed A1/2+B0 mapping and October7 04:00UTC compute/analysis deadline. It does not alter the original Sand numerical trainer, evaluator, converter, protocol or old quota-v2 files. Templates are deliberately not admitted. Root supplies actual immutable paths, complete hashes, process evidence and mode-specific authorization.

## Ordering and allocation

1. Both Sand training supervisors and all their children must have exited successfully, including endpoint audits. Inventory each completed host while its files are stable. All six exact100000-step endpoints, all11 saved checkpoints/model, optimizer/history/source verification and three paired seeds are prerequisites. No endpoint selection, retry or partial-cohort test access.
2. Root freezes one complete six-model cohort. Allocate up to2700seconds for cohort/source verification. The adapter inherits the already reviewed supervisor's endpoint tensor/Adam/history conclusions; it hashes retained bytes, without pretending to perform another tensor audit.
3. Root opens one shared preparation window of at most900seconds, finishing by23:44UTC minus clock uncertainty. Acquisition, conversion, full1060-trajectory numeric duplicate census, candidate admission and final preflight all use this same start/stop; mode boundaries do not reset it. Stage only on explicit root mode releases. Validation data already admitted for training remains distinct from newly acquired test data.
4. Run six final streams concurrently: B(base0/GPU2,mix0/GPU3); A(base1/GPU0,mix1/GPU1,base2/GPU2,mix2/GPU3). Each stream runs full test rollout7200s, validation same-state1800s, test same-state1800s and clean validation900s, with15s cleanup/stage:11760s total. Reserve3600s afterward for full failure accounting and analysis. Latest queue start is23:44UTC minus clock error; final evaluation ends by03:00 and analysis by04:00. These are engineering allocations, not measured co-residency bounds.

Root must verify the complete pipeline still fits before training admission. No two-GPU three-wave fallback is implied. The wrappers observe all GPU processes and control only their own admitted children/devices. B0/1 can host separately admitted Goop work; this Sand queue owns B2/3 only.

Use `prepare_sand_final_cohort_scoped_v1.py` with explicit `--execute --mode inventory --host-root ABS --process-check ABS --output ABS`, once on each host. The output lies outside the inventory tree. Root process evidence uses `sand_completed_host_process_check.template.json`, fresh within1800s, empty matching training process list, actual exited supervisor identity and all children reaped. The inventory verifies its complete file tree and captured scalar/process bytes immediately before exclusive publication.

After transferring the two small inventories, use `--mode build --inventory-a ABS --inventory-b ABS --root-release ABS --output-dir NEW_ABS`, plus the `--protocol`, `--train-admission`, `--trainer-source`, `--benchmark-helper` and `--diagnostic-source` paths named by `FINAL_PINS`. `sand_final_cohort_scoped_release.template.json` specifies the root release shape. Each evaluation host needs its assigned checkpoints; the frozen evaluator uses the complete root audit for members retained on the other host. No unnecessary checkpoint replication is required. The adapter publishes exact copied root release, audit and then cohort, with terminal hash rechecks; failures remain in place.

## Reserved test preparation

Use `prepare_sand_reserved_test_scoped_v1.py --execute --mode MODE --cohort ABS --cohort-audit ABS --root-release ABS --output-dir NEW_ABS`. Every mode gets a fresh output directory and separate exact root release (`sand_reserved_test_scoped_release.template.json`). Root sets `status=approved_for_MODE`, `issued_by=root`, full source/input SHA256 map and the common preparation window. All six endpoints and complete paired audit are checked before test or acquisition input access.

- `acquire`: calls the frozen downloader in process, requesting only `test.npz` plus metadata. Downloader return2 is accepted only with the complete object-dtype report. The wrapper verifies85825802 test bytes,363 metadata bytes, exact metadata SHA and30ZIP members. There is no publisher-independent test SHA; the freshly acquired hash is recorded without claiming otherwise. No arrays are decoded here.
- `convert`: add `--input-dir ABS --acquisition-report ABS`; bind both source files and the report in the root release. Reuse the frozen restricted protocol3/three-NumPy-global decoder. Require all30 trajectories,T320,D2,<f4,type6 and preservation of dtype/shape/values. Publish `test.json` last. Failed staging and original source remain.
- `census`: add `--train-manifest ABS --valid-manifest ABS --test-manifest ABS`. Bind the exact original training manifest and all manifests. Read numeric arrays with `allow_pickle=False`, verify bytes/logical content, and compare every train1000+valid30+test30 trajectory within/across splits. No decoding or evaluation occurs. Output `all_split_census.json` binds all2120 numeric files and all1060 identities.
- `candidate`: add `--split valid|test` and all three `--train-manifest ABS --valid-manifest ABS --test-manifest ABS`, plus `--census-report ABS --structural-report ABS --protocol ABS --train-admission ABS`. The complete2120-file census map is derived again from all three bound manifests and compared exactly, and every numeric file is hash-rechecked at publication. The frozen evaluator's split contract is checked in memory, then a **non-admitted** `split_admission_candidate.json` is saved for independent root review. Root records its review in a separate signed admission with `issued_by=root`, `status=admitted_for_final_evaluation`, preserved census hash and unchanged contract fields.
- `preflight`: same inputs as candidate plus `--admission ABS`, bound in the root release. Requires root-issued final admission bound to the full census and runs unchanged evaluator split checks. Outputs `split_preflight.json`. Repeat separately for validation and test within the original common window.

All modes enforce remaining wall time with an in-process alarm. Fresh preparation failure preserves `failed_preparation.json` and any partial source/staging. Never relabel failure as complete or reset the900s window implicitly.
