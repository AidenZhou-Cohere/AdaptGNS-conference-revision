# Sand graph-support evaluation adapters

Prepared for independent review and later root release. No source is frozen by these notes, and no actual Sand trajectories, checkpoints, scientific model, test source or CUDA execution were used by this agent. Existing feasibility, final-diagnostic and numerical-helper files remain unchanged. The three new modules and their synthetic tests are separate from the earlier faithful/NLL lineage.

## New modules

`sand_graph_support_policy.py` adds `relative-velocity-RMS25`. The five existing policies call the pinned native rollout directly. The new physical rollout uses an explicit copy of that loop with a local physical-graph callback; no imported module globals are patched. Its native graph construction, normalized model call, failure guards, accepted-prefix accounting, physical boundaries and trace rules retain the earlier definitions.

The score is the RMS Euclidean difference between a particle's last-step physical velocity and its retained incoming native-base nonself senders. The implementation casts the two observed positions to float64 before subtracting/dividing by the metadata timestep, computes squared 2D differences in float64, accumulates them in native edge order with `numpy.add.at`, divides by integer incoming nonself counts and takes the square root. Isolated scores are zero. The timestep is 0.0025 from pinned Sand metadata. Scores measure local relative motion; they are not uncertainty estimates. Cap asymmetry and omitted self candidates remain as observed in the native graph.

The existing selector ranks strict-annulus pairs by max endpoint score, using its stable lexicographic ties, and chooses exactly floor(0.25 × annulus count). Symmetric optional edges append after the unchanged native directed cap128/self prefix and are never recapped. Scoring, ranking and their graph work are included in measured call time. The common-state outputs save the exact float64 selection scores; graph ledgers save their hash and support-count hash, including every accepted physical-policy rollout step.

`benchmark_sand_graph_support_rollout.py` is **timing-only infrastructure**. Its CLI admits only explicitly selected 512-update graph-support checkpoints, faithful base/mix, seeds 0/1/2, checkpoint cadence 10000 and log cadence 1, with a separate root timing release. It rejects initialized models, final100k promotion through the timing CLI and test inputs. The selected checkpoint contract is also reused by the final entry, where it requires100000 updates and log cadence100.

Timing modes are `--diagnostic-mode full-rollout`, `same-state` or `clean-validation`. All select the source-small/lower-median/large cases prospectively by particle count then source index. Full rollouts use complete T−6 horizons under all six policies. The two diagnostic timing modes accept validation only and use targets7,85,163,241,319 for each of the three selected cases, with the pinned final diagnostic functions. Every diagnostic call records synchronized time including parity, warmup and audits; numeric-artifact publication time is separate. Setup, verification, JSON publication and overall execution are also retained at invocation level. Guarded prefixes or missing outcomes do not become complete-horizon estimates. Timing evidence alone does not admit a cost forecast or scientific study.

`evaluate_sand_graph_support_final.py` supports final `clean-validation`, `same-state` and `full-rollout` modes. It requires the root's complete six-member base/mix × seeds0/1/2 audit and frozen cohort before opening an evaluation manifest. It verifies the selected checkpoint bytes and then validates/loads its payload once, avoiding a second100k-ledger deserialization. Final clean validation retains the128 prescribed distinct histories and variance-floor metrics. Same-state uses all30 trajectories × five fixed targets, all six policies plus natural-base reference, and seven balanced timing rounds. With the risk policy's extra score pass this is68 network forwards per frame including parity and warmup. Full rollouts evaluate all30 trajectories and all314 forecasts under six policies for the selected arm/seed:180 outcomes per invocation,1080 across the six-model cohort. Complete-cohort paired analysis remains a separate step.

## Root-issued final cohort and audit

The cohort schema is `adaptgns_sand_graph_support_final_cohort_v1`, status `frozen_for_final_evaluation`, dataset Sand, updates100000 and training_schema `adaptgns_sand_graph_support_cuda_training_v1`. It pins `protocol_sha256`, `training_admission_sha256`, `trainer_source_sha256`, `benchmark_helper_sha256`, `diagnostic_source_sha256` and `cohort_audit_sha256`; it declares deterministic_algorithms true and CUBLAS_WORKSPACE_CONFIG `:4096:8`. Its policy list is the six rollout names above. Six distinct `models` rows bind faithful objective, base/mix arm, seed0/1/2, completed_steps100000 and checkpoint_sha256.

The file supplied as `--cohort-audit` has schema `adaptgns_sand_graph_support_complete_cohort_audit_v1`, status `all_six_endpoints_and_pairing_verified`, the exact training schema and the same protocol/training-admission/trainer hashes. This audit is produced only after root verifies all six actual checkpoint files, endpoints, optimizer state and pairings, including models on the second host. A declaration without performing that audit is insufficient.

Each of its six `models` rows must match arm, seed and checkpoint_sha256, declare completed_steps and graph_history_updates100000, checkpoint_every10000 and log_every100, and have true values for `all_optimizer_steps_equal_100000`, `all_state_and_moments_finite`, `source_data_protocol_verified` and `checkpoint_bytes_verified`. Each of three `paired_seeds` rows binds its seed and true values for `initial_model_tensor_identity`, `initial_cpu_cuda_rng_identity`, `all_frame_noise_lr_schedules_equal` and `all_graph_budgets_and_rng_material_verified`. Root must retain underlying checks and hashes; the final entry relies on this pinned completed audit for other-host members, then verifies its selected file and payload. It does not claim to deserialize all six checkpoints on every invocation.

Final split admission uses schema `adaptgns_sand_graph_support_final_evaluation_admission_v1`, status `admitted_for_final_evaluation`, and binds the final cohort, scientific protocol, training admission, source, converter, structural report and exact numeric manifest. All30 records, T320, type6, float32 positions, source order and preserved logical values remain mandatory. The existing declared test-source acquisition and review gate still applies. No evaluation adapter acquires data.

## Checks and limits

Thirty-seven focused synthetic/mock tests currently pass. They cover default nonexecution; exact incoming RMS and invariances; isolated/capped neighborhoods; exact budgets and ties; core-policy delegation; mocked physical full rollout and adverse outputs; checkpoint lineage/recipe/schedule rejection; timing-release identities; complete-cohort and pairing-audit rejection before test reads; clean variance interpretation; target isolation; repeated physical/risk score checks; seven-slot timing balance; synchronized diagnostic timing; fixed final rollout dispatch; and missing/failing outcome null coverage.

See `sand_graph_support_evaluation_synthetic_tests.log`, `sand_graph_support_evaluation_source_delta.json` and the independent review for hashes and scope. These are implementation checks, not actual Sand outcomes, numerical backend admission, measured GPU capacity, scientific release or conference readiness.
