# Code and reproducibility audit

Audited the public release at commit `5cf0d7cb9d927f4277c4538917ae570d8dc9d7b6` against the paper and the two supplied reviews. The corrections below are implemented in `outputs/AdaptGNS/adaptive-gns/`; the committed historical result arrays are unchanged. These fixes require rerunning the experiments before replacing published numerical claims.

## Findings that can change the scientific conclusions

1. **The released training loss is not the Gaussian NLL written in the paper.** The head returns `Softplus(h)`. The original trainer interprets this as a standard deviation, squares it, and minimizes `||e||²/(2v) + 0.5 log(v)`. The paper describes Softplus as variance and specifies `||e||²/(2v) + (d/2) log(v)`. In two dimensions, the released objective has a factor-of-two error in its log penalty. For a fixed residual, differentiating gives `v*=||e||²` in the release and `v*=||e||²/d` under the stated model. Joint mean/variance optimization and reported calibration therefore cannot be equated to the paper's stated objective.
2. **Evaluation uses different normalization from training.** Training constructs acceleration and velocity scales as `sqrt(data_std² + noise_std²)` with a default `noise_std=6.7e-4`. Both released rollout evaluators and calibration evaluation construct their model with zero in this formula. This changes the input features and the inverse transformation of the output; setting the input perturbation to zero does not justify changing the trained normalization. With the committed metadata, the training/evaluation acceleration-scale ratios are **2.780 and 2.478 for Sand**, and **10.285 and 8.471 for WaterDrop**. The corresponding velocity ratios are 1.045/1.031 and 1.109/1.123. Old checkpoints contain weights only, so the correct scale cannot be recovered from checkpoint tensors alone. Historical result files do not identify which evaluator revision generated them; this audit establishes a code-path discrepancy, not the exact settings used in every historical run.
3. **The stated validation-selection protocol cannot be reproduced from the released sweep command.** The paper says the percentile/radius sweep used validation trajectories. The released adaptive evaluator unconditionally reads `test.npz`, and the supplied sweep job invokes it without another split mechanism. Separately, `gns.train --mode=valid` checks the literal string `"{FLAGS.data_path}valid.npz"`, without interpolation, and consequently falls back to test in ordinary use. The exact historical selection procedure needs author confirmation or logs; it should not be asserted to be validation-only from this release alone.
4. **The default baseline evaluator cannot load all described baselines.** It always constructs ten message-passing layers and a variance head. Strict loading rejects upstream mean-only checkpoints because they lack the head, and a zero-message-passing MLP needs its own architecture. Radius changes also affect edge and boundary feature scaling and must be recorded alongside graph topology.
5. **There is no basis for a direct runtime claim from one forward pass or edge totals alone.** The adaptive implementation runs both the base and expanded-radius searches over every particle, filters incident edges, and performs `torch.unique`. It does not restrict the expanded search itself to selected particles. The radius kernel caps neighbors at 128, and self-loops plus both directed orientations are counted. The union preserves all base edges on identical positions; lower rollout edge counts than a base graph therefore involve changes in predicted geometry. The OR-endpoint rule can add neighbors to unselected particles too. A percentile threshold is not an exact edge budget, and tied scores can select fewer particles than the nominal fraction.
6. **The variance-head parameter claim is inconsistent with the release.** The implemented `128 → 128 → 128 → 1` MLP has **33,153 parameters**, not fewer than 20,000. Keeping this architecture preserves checkpoint compatibility; the manuscript should report its actual size.
7. **Calibration has additional sampling and indexing issues.** The released default processes only the first 100 sequential validation minibatches, potentially concentrating on the earliest trajectory. Percentile boundaries plus a fixed `1e-9` adjustment are fragile for tied or large-valued predictions. Spatial plot labels use one-based steps but index arrays without subtracting one. The metric is a binned regression calibration discrepancy in squared normalized-acceleration units, not classification ECE or proof of epistemic uncertainty.

## Implemented corrections

- `gns/losses.py` implements the dimension-correct NLL with the head interpreted as per-coordinate variance, and explicitly preserves the released computation as `--loss=legacy_nll`. `--loss=mse` enables comparable baseline training in this checkout. Its architecture retains an unused variance head, so inference risk/calibration evaluation rejects these checkpoints; fixed-graph mean evaluation remains available. Empty dynamic-particle batches fail clearly, and kinematic states are removed before loss arithmetic.
- `--loss=faithful` adds a mean-preserving heteroscedastic objective: the mean term is the same sum-of-coordinates MSE used by this trainer, the variance head receives detached features, and its likelihood receives detached squared residuals. A regression test verifies identical mean/trunk gradients to MSE and nonzero trainable variance-head gradients. This implements a known faithful heteroscedastic-regression idea; it is not claimed as a novel loss. Shared gradient clipping is absent in this trainer, so it does not reintroduce coupling. The lightweight research pilot uses a `0.5*SE` mean convention, whereas the original trainer keeps its existing `SE` convention.
- New checkpoint format version 2 stores architecture, normalization tensors, radius, variance semantics/floor, graph backend/cap, and training flags including seed. `gns/model_io.py` reconstructs these rather than guessing. Legacy checkpoints produce explicit warnings and assume the released `6.7e-4` normalization unless overridden. `--normalization_noise_std=0` is available for forensic replication of the old evaluator, not the recommended trained-model evaluation.
- Evaluation defaults to `--split=valid`, incorporates the split into default output names, and writes provenance. Test evaluation is explicit. The standard `gns.train --mode=valid` path now uses validation without fallback and reconstructs checkpoint configuration. Evaluators support partial/available horizons, report longer horizons when available, and count only dynamic particles in MSE. The real WaterDrop files have 1001 stored frames; with six context frames there are **995 forecasts**, so a 1000-step forecast requires additional ground truth.
- Training exposes seed, radius, depth, loss, and graph-backend settings. Saving occurs after incrementing the completed optimizer-update count, correcting the original off-by-one checkpoint labels. Training uses the module's actual `forward` entry so DDP can install its synchronization hooks; distributed samplers receive the epoch. Multi-GPU correctness remains unverified here.
- Adaptive percentile selection is independent per trajectory in a batch. Base edges and graph orientation are covered by regression tests. Strict-quantile tie behavior is retained and documented.
- Calibration uses the checkpoint's variance parameterization and trained normalization, defaults to all validation minibatches, preserves ties in a bin, includes the maximum prediction, writes counts/provenance, and fixes the plot-step offset.
- `--radius_backend=scipy` is an **explicit CPU reference implementation**, permitting full original-model execution without `torch_cluster`. It respects batching, self-loop choice and strict-radius selection. At the 128-neighbor cap it deterministically chooses nearest neighbors; this can differ from PyG's capped selection, and CPU reference timings must not be presented as GPU performance.
- `scripts/evaluate_budget_policies.py` evaluates original checkpoints on identical ground-truth histories with equal incremental undirected-pair budgets for random, speed, and lagged-risk allocation. Base and full-radius controls are included. Both directions and self-loops are counted; data/checkpoint hashes, sampled frame IDs and synchronized timing components are saved. It reuses the uncapped SciPy pair builder in `research/budget_graph.py`; its non-strict boundary convention and lack of the original neighbor cap are explicitly recorded. This is a teacher-forced diagnostic, not evidence of free-rollout stability. The risk at each evaluated state comes from the risk policy's preceding graph, initialized by a base-graph warmup.

## Verification completed locally

- `work/venv/bin/python -m pytest outputs/AdaptGNS/tests -q`: **16 passed**. Tests cover analytic NLL values and variance optimum; explicit legacy behavior; exclusion of kinematic NaNs; trajectory-local quantiles/ties; graph union, batching and feature parity; one neural pass per adaptive rollout step; partial horizons; saved architecture/normalization; strict upstream checkpoint exceptions; noise normalization; calibration ties; exact head size; one actual optimizer update and checkpoint count; faithful-gradient equivalence; real SciPy graph construction; and equal edge budgets across allocation controls.
- The tiny graph tests use an independent exact-radius oracle where appropriate. The explicit SciPy backend is separately exercised with real `cKDTree` construction.
- An actual **CLI integration run** used the original 128-wide, ten-message-passing-layer architecture on an official WaterDrop training trajectory (678 particles), followed by a distinct validation trajectory (482 particles). Each trajectory was truncated to 12 frames solely for smoke testing. Two faithful optimizer updates, saved-checkpoint reconstruction, six-step fixed rollout, six-step adaptive rollout, `gns.train --mode=valid`, two equal-state budget windows and two calibration minibatches completed on CPU. No `test.npz` was present in this smoke directory, so the successful validation command also checks that the old silent test fallback is gone. **These two updates are not a scientific training run and their losses must not be cited as performance evidence.**
- The smoke run's fixed and adaptive MSE at forecast step 1 were both `1.8717239314014478e-08`, as expected because the first graph is identical. The purpose is integration verification, not benchmarking. Full provenance is recorded in `full_pipeline_smoke.json` beside this report.

## Work still required before conference-level claims

Recover or retrain the full models with corrected normalization/objective and immutable data splits; publish checkpoint files, training configurations, data hashes and trajectory IDs. Freeze hyperparameters on validation before test evaluation. Train multiple independent seeds with matched optimization budgets, and retain both faithful/MSE and corrected-NLL baselines. Report trajectory and training-seed uncertainty separately. Run matched-allocation random/speed/risk controls, then actual free rollouts with a budgeted policy. Measure graph construction, selection, neural forward, synchronization and peak memory on the intended hardware. Quantify whether lagged scores predict the benefit of an added edge; ranking residuals alone does not establish this. Evaluate the full available horizon and stability failures.

The inherited full upstream test suite, CUDA radius kernels, multi-node trainer, distributed optimizer synchronization and exact mid-epoch restart reproducibility have not been validated in this environment. A saved seed is not a guarantee of bitwise reproducibility across devices or interrupted sampler states. The separate multinode script still needs a dedicated modernization pass; only its duplicate flag-registration import was corrected. The old result tables cannot be retrospectively certified by fixing source code.
